## Overview

Blocks are individual steps of [workflows](/workflows/overview), with configurable **properties** and **exit nodes**. Properties control the block's behavior and appearance, while exit nodes define the paths [users](/users/overview) take after interacting with the block.

## Block name and description

Every block includes a name and description. The name is displayed in the workflow, while the description can be used to provide additional context about the block.

![Block name and description](/workflows/block-name.png)

## Block properties

[Block properties](/blocks/block-properties/overview) define a block's behavior and appearance. Access these properties in the block edit panel. Hover over a property name to view additional details, such as description, key, and type.

## Exit nodes

Exit nodes are transitions triggered by user interactions with a block. Each exit node in the block edit panel shows what moves the user through it and where it leads. To connect one:

1. Click the exit node to open its detail.
2. Click the **`+`** button beside **Connections**.
3. Select the destination block(s) to connect.

Each exit node can transition to multiple blocks. If no blocks are connected, the user instance stops at the current block. However, the workflows may continue if user is currently in other blocks.

![Exit nodes](/workflows/exit-nodes.png)

### Triggers

Triggers are what move a user through an exit node. Every exit node has a default trigger that depends on the block type, such as a click on a component, an elapsed [delay](/blocks/logic-blocks/delay), or a completed [tour](/blocks/tour-block).

You can add extra triggers, so the user also continues without interacting with the block:

- **User properties**: the user continues when their [user properties](/blocks/block-properties/user-properties) start matching. Flows evaluates it when the user enters the block and when it receives updated properties for the user.
- **Delay**: the user continues once the set time passes since they entered the block, for example a banner that closes itself after 7 days. The delay is at least 1 minute and at most 30 days, and Flows checks it every minute.

To add a trigger:

1. Click the exit node to open its detail.
2. Click the **`+`** button beside **Trigger** and select **User properties** or **Delay**.
3. Click the new trigger and define the conditions or the delay duration.

When an exit node has multiple triggers, **any** of them moves the user on. When triggers of several exit nodes fire at the same time, the user continues through all of them.

<Callout>
  The user properties trigger is available on components, surveys, tours and delays. Start,
  manual start and filter blocks already evaluate user properties as their own block property, so
  their exit nodes have no separate user properties trigger. The delay trigger is available on
  components, surveys and tours. A [delay](/blocks/logic-blocks/delay) block uses its own delay
  duration instead.
</Callout>

## Block positioning

You can drag and drop blocks within the workflow editor to adjust their visual layout. Note that position changes do not affect block functionality.

## Duplicating a block

To duplicate a block:

1. Click the **`•••`** menu in the block's edit panel.
2. Select **Duplicate block**.

This creates a new block with the same properties and exit nodes, which you can then modify as needed.

## Removing a block

To remove a block:

1. Click the **`•••`** menu in the block's edit panel.
2. Select **Delete block**.

This removes the block and disconnects all associated paths.
